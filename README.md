# 10초만 살아남아라

PC·모바일 웹에서 즐기는 네온 스타일 2D 생존 아케이드. 생존 시간이 점수이며, 기록은 현재 브라우저에만 저장됩니다.

## 실행

Node.js 22 이상을 권장합니다. 게임 자체에는 런타임 패키지가 없습니다.

```sh
npm ci
npm start
# http://localhost:4173
```

방향키/WASD 또는 화면 아무 곳에서 상대 드래그로 이동합니다. 드래그는 캐릭터를 손가락 아래로 순간이동시키지 않으며 키보드와 같은 최대 속도로 이동합니다. ESC/P 또는 버튼으로 일시정지하고 Enter/버튼으로 재도전합니다. 탭 비활성화, 창 포커스 해제, 크기 변경 시 자동으로 멈춥니다. 자동 재개되지 않습니다. 소리는 기본 OFF이며 버튼으로 켭니다.

## 게임 규칙과 밸런스

- 첫 2초 적응 시간. 작은 플레이어 중심의 반지름 7만 실제 충돌 판정에 사용합니다.
- 시작 전 2초 적응 후 각 패턴이 5초 동안 끝까지 공격합니다. 이후 마지막 공격을 피하는 마무리 구간을 거쳐 다음 패턴으로 이어집니다. 실제 단계 길이는 마지막 공격의 경로에 따라 달라집니다.
- 유성우는 기울기가 번갈아 바뀌고, 틈새 비행은 한 방향에서 이어지는 통로가 서서히 움직입니다. 레이저는 세로→가로 연계를, 파동은 양쪽 교대 발사와 열린 틈을 사용합니다. 기존의 2배 템포는 유지합니다.
- 공격 종료 1.25초 전부터 다음 패턴·회피 요령을 미리 표시하고 배경색이 서서히 이어집니다. 이전 장애물이 모두 퇴장한 직후 다음 공격을 시작하며, 다음 패턴의 첫 통로는 플레이어가 빠져나온 위치를 이어받습니다. 전환 시 이동 입력·궤적을 초기화하거나 장애물을 강제로 삭제하지 않습니다.
- 레이저는 실제 시간 기준 0.9~1.1초 동안 카운트다운을 보여 주며, 공격 사이 최소 0.2초의 여유를 둡니다. 레이저는 동시에 겹쳐 발사되지 않습니다. 방사탄은 가장자리 발사원을 0.425초 예고합니다. 점수와 플레이어 이동은 실시간 기준입니다.
- 판마다 패턴 계획을 새로 뽑습니다. 유성우의 기울기·안전 열·간격, 통로의 진입 방향·폭·이동 경로, 레이저의 방향·타깃·간격, 파동의 발사 높이·부채꼴 각도·열린 틈이 달라집니다. 통로는 가장자리까지 이동하지만 이동량을 플레이어가 도달 가능한 거리 이내로 제한합니다.
- 장기 생존 시 속도와 빈도가 완만하게 증가하고 상한에 수렴합니다. 레이저 예고 시간은 난도가 올라도 0.9초 미만으로 줄이지 않습니다. 개별 공격에는 회피 경로가 있지만, 플레이어의 위치와 이동에 따라 후속 공격에 갇힐 수 있으므로 미리 이동해야 합니다.
- 이동량은 게임 좌표 기준 초당 250. 모든 기기는 600×640 논리 좌표와 동일한 충돌 판정을 사용합니다. 화면에는 기기 크기에 맞춰 표시합니다.
- 소리는 Web Audio 합성이며 외부 이미지·음원·폰트가 없습니다. 저장 제한 환경에서도 게임을 계속할 수 있고 저장 불가를 결과 화면에 알립니다.

## 구조

- `src/game.js`: 상태 전이, 시간, 프레임 기반 물리 (최대 1/120초 세부 스텝)
- `src/patterns.js`: 4종 패턴과 점근적 난도
- `src/collision.js`: 독립 충돌 판정
- `src/main.js`: DOM, 키보드/포인터 입력, 생명주기
- `src/render.js`: Canvas 렌더링, DPR 최대 2, 저감 모션 지원
- `src/storage.js`, `src/audio.js`: 저장과 합성 음향
- `tests/`: Node 단위/시뮬레이션 테스트, Playwright 브라우저 테스트

단일 requestAnimationFrame 루프를 유지하며 재시작 시 타이머/장애물/입력을 초기화합니다. 장애물·파티클 수명과 배열 크기를 제한합니다. 백그라운드 시간은 점수에 포함하지 않고, 긴 프레임은 0.1초로 제한해 순간이동과 충돌 누락을 방지합니다.

## 검증

```sh
npm test
npx playwright install chromium  # 최초 1회; Linux는 --with-deps가 필요할 수 있음
npm run test:browser
npm run build
SERVE_DIR=dist npm start
```

브라우저 테스트는 자체 HTTP 서버를 시작하고 종료합니다. 시스템 Chromium을 쓰려면 `CHROMIUM_PATH=/usr/bin/chromium`을 지정합니다. `test-results/`에 데스크톱·모바일 화면을 저장합니다. 터치 테스트는 Chromium의 모바일 에뮬레이션이며 실제 iOS/Android 기기 검증은 별도입니다.

## GitHub Pages

`.github/workflows/pages.yml`이 main push 시 테스트와 정적 빌드 후 `dist/`를 배포합니다. PR에서는 테스트만 수행합니다. 워크플로는 `contents: read`, `pages: write`, `id-token: write`를 선언합니다.

Repository Settings → Pages → Source를 **GitHub Actions**로 선택해야 합니다. 환경 보호 규칙이 있으면 배포 승인이 필요할 수 있습니다. 배포 주소는 Actions의 Deploy 결과에서 확인하세요. 이 레포지토리의 기본 주소는 https://ys143112.github.io/testing_ai/ 입니다.

CSS, 모듈, favicon은 모두 상대 경로이므로 프로젝트 하위 경로에서도 동작합니다. `dist/`에는 게임 파일만 포함되며 서버나 비밀 키가 필요하지 않습니다.

배포 빌드는 모든 JavaScript 모듈과 CSS를 내용 해시가 포함된 경로에 배치합니다. 하위 모듈 하나만 수정해도 전체 모듈 경로가 바뀌어 이전 캐시와 섞이지 않습니다. GitHub Pages는 HTML 자체를 최대 10분 캐시할 수 있으므로 즉시 확인할 때는 `?v=<dist/version.json의 version>`을 주소에 붙이세요. Actions 브라우저 테스트는 실제 `dist/` 산출물을 검사합니다.

### 순환 강화

1패턴은 매번 상하좌우 중 한 방향에서 시작합니다. 2회차부터 주 공격이 반대편과 교대하고 측면 예고탄이 함께 나오며, 3회차부터 사방을 순환합니다. 안전 열도 두 열에서 한 열로 줄어듭니다.

2패턴은 2회차부터 같은 열린 통로를 공유하는 반대편 벽과 측면 예고탄을 추가합니다. 겹쳐 있는 벽들은 최소 44 게임 좌표 폭의 공통 통로를 유지합니다. 3회차부터 측면 공격 빈도가 올라갑니다. 단계 번호와 순환 횟수는 계속 올라가고, 구조적 강화와 속도·빈도 가중치는 4회차 수준에서 상한에 도달합니다. 레이저의 0.9초 이상 예고·비중첩 규칙은 그대로 유지합니다.
