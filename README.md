# 10초만 살아남아라

PC·모바일 웹에서 즐기는 네온 스타일 2D 생존 아케이드. 생존 시간이 점수이며, 기록은 현재 브라우저에만 저장됩니다.

## 실행

Node.js 22 이상을 권장합니다. 게임 자체에는 런타임 패키지가 없습니다.

```sh
npm ci
npm start
# http://localhost:4173
```

PC에서는 방향키/WASD 또는 마우스 좌·우클릭으로 이동합니다. 클릭한 지점까지 버튼을 놓아도 계속 이동하며, 도착하면 멈춥니다. 새 클릭은 목적지를 바꾸고 키보드 이동은 클릭 명령을 취소합니다. 마우스 커서를 움직이는 것만으로는 목적지가 바뀌지 않습니다. 모바일·펜은 상대 드래그를 사용하고 손을 떼면 멈춥니다. 모든 조작은 키보드와 같은 최대 속도(1×에서 초당 250)와 충돌 판정을 쓰며 순간이동하지 않습니다. 일시정지·탭 전환·리사이즈·재도전 시 목적지를 초기화합니다. ESC/P 또는 버튼으로 일시정지하고 Enter/버튼으로 재도전합니다. 탭 비활성화, 창 포커스 해제, 크기 변경 시 자동으로 멈춥니다. 자동 재개되지 않습니다. 소리는 기본 OFF이며 버튼으로 켭니다.

## 게임 규칙과 밸런스

- 첫 2초 적응 시간. 작은 플레이어 중심의 반지름 7만 실제 충돌 판정에 사용합니다.
- 시작 전 2초 적응 후 각 패턴이 5초 동안 끝까지 공격합니다. 이후 마지막 공격을 피하는 마무리 구간을 거쳐 다음 패턴으로 이어집니다. 실제 단계 길이는 마지막 공격의 경로에 따라 달라집니다.
- 유성우와 틈새 비행은 매 공격의 진입 방향이 달라지고, 열린 공간을 연결하며 이동해야 합니다. 레이저는 방향을 바꾸는 연계를, 파동은 양쪽 교대 발사와 열린 틈을 사용합니다. 기존 대비 1.5배 템포는 유지합니다.
- 공격 종료 1.25초 전부터 다음 패턴·회피 요령을 미리 표시하고 배경색이 서서히 이어집니다. 이전 장애물이 모두 퇴장한 직후 다음 공격을 시작하며, 다음 패턴의 첫 통로는 플레이어가 빠져나온 위치를 이어받습니다. 전환 시 이동 입력·궤적을 초기화하거나 장애물을 강제로 삭제하지 않습니다.
- 레이저는 실제 시간 기준 1.05~1.2초 동안 경고 띠 양쪽의 충전선이 중앙으로 모이고 원형 게이지가 차오르며, 공격 사이 최소 0.2초의 여유를 둡니다. 레이저는 동시에 겹쳐 발사되지 않습니다. 방사탄은 가장자리 발사원을 0.425초 예고합니다. 점수와 플레이어 이동은 실시간 기준입니다.
- 판마다 패턴 계획을 새로 뽑습니다. 유성우의 기울기·안전 열·간격, 통로의 진입 방향·폭·이동 경로, 레이저의 방향·타깃·간격, 파동의 발사 높이·부채꼴 각도·열린 틈이 달라집니다. 통로는 가장자리까지 이동하지만 이동량을 플레이어가 도달 가능한 거리 이내로 제한합니다.
- 장기 생존 시 속도와 빈도가 완만하게 증가하고 상한에 수렴합니다. 레이저 예고 시간은 난도가 올라도 1.05초 미만으로 줄이지 않습니다. 개별 공격에는 회피 경로가 있지만, 플레이어의 위치와 이동에 따라 후속 공격에 갇힐 수 있으므로 미리 이동해야 합니다.
- 1×에서 이동량은 게임 좌표 기준 초당 250. 모든 기기는 600×600 논리 좌표와 동일한 충돌 판정을 사용합니다. 화면에는 기기 크기에 맞춰 표시합니다.
- 소리는 Web Audio 합성이며 외부 이미지·음원·폰트가 없습니다. 저장 제한 환경에서도 게임을 계속할 수 있고 저장 불가를 결과 화면에 알립니다.

## 구조

- `src/game.js`: 상태 전이, 시간, 프레임 기반 물리 (최대 1/120초 세부 스텝)
- `src/patterns.js`: 8종 패턴과 점근적 난도
- `src/collision.js`: 독립 충돌 판정
- `src/main.js`: DOM, 키보드/포인터 입력, 생명주기
- `src/render.js`: Canvas 렌더링, DPR 최대 2, 저감 모션 지원
- `src/storage.js`, `src/audio.js`: 저장과 합성 음향
- `tests/`: Node 단위/시뮬레이션 테스트, Playwright 브라우저 테스트

단일 requestAnimationFrame 루프를 유지하며 재시작 시 타이머/장애물/입력을 초기화합니다. 장애물·파티클 수명과 배열 크기를 제한합니다. 백그라운드 시간은 점수에 포함하지 않고, 긴 프레임은 0.1초로 제한해 순간이동과 충돌 누락을 방지합니다.

## 검증

```sh
npm test
npx playwright install chromium  # 최초 1회; Linux는 --with-deps가 필요할 수 있음
npm run test:browser
npm run build
SERVE_DIR=dist npm start
```

브라우저 테스트는 자체 HTTP 서버를 시작하고 종료합니다. 시스템 Chromium을 쓰려면 `CHROMIUM_PATH=/usr/bin/chromium`을 지정합니다. `test-results/`에 데스크톱·모바일 화면을 저장합니다. 터치 테스트는 Chromium의 모바일 에뮬레이션이며 실제 iOS/Android 기기 검증은 별도입니다.

## GitHub Pages

`.github/workflows/pages.yml`이 main push 시 테스트와 정적 빌드 후 `dist/`를 배포합니다. PR에서는 테스트만 수행합니다. 워크플로는 `contents: read`, `pages: write`, `id-token: write`를 선언합니다.

Repository Settings → Pages → Source를 **GitHub Actions**로 선택해야 합니다. 환경 보호 규칙이 있으면 배포 승인이 필요할 수 있습니다. 배포 주소는 Actions의 Deploy 결과에서 확인하세요. 이 레포지토리의 기본 주소는 https://ys143112.github.io/testing_ai/ 입니다.

CSS, 모듈, favicon은 모두 상대 경로이므로 프로젝트 하위 경로에서도 동작합니다. `dist/`에는 게임 파일만 포함되며 서버나 비밀 키가 필요하지 않습니다.

배포 빌드는 모든 JavaScript 모듈과 CSS를 내용 해시가 포함된 경로에 배치합니다. 하위 모듈 하나만 수정해도 전체 모듈 경로가 바뀌어 이전 캐시와 섞이지 않습니다. GitHub Pages는 HTML 자체를 최대 10분 캐시할 수 있으므로 즉시 확인할 때는 `?v=<dist/version.json의 version>`을 주소에 붙이세요. Actions 브라우저 테스트는 실제 `dist/` 산출물을 검사합니다.

### 방향 혼합과 단계별 난도

게임 영역은 PC·모바일 모두 600×600 논리 좌표의 정사각형입니다. CSS 표시 영역도 1:1을 유지하고 화면을 늘이거나 내부 여백으로 맞추지 않습니다.

1·2패턴은 첫 등장부터 한 패턴 안에서 상하좌우와 대각선의 8방향 진입을 섞습니다. 여덟 방향을 한 번씩 사용한 뒤 순서를 다시 섞고, 직전 방향이 바로 반복되지 않도록 합니다. 유성우의 방향 예고는 약 0.87초, 벽의 예고는 1초입니다. 서로 다른 방향의 벽이 겹쳐도 회전한 벽의 모든 통로를 기하학적으로 교차시켜 충분한 공통 회피 공간을 유지합니다.

5단계에서 속도·밀도·안전 열·추가 공격을 동시에 강화하던 규칙은 제거했습니다. 속도와 빈도의 가중치는 단계마다 조금씩 증가하며 상한에 수렴합니다. 5단계는 기본 두 안전 열을 유지하고 추가 탄을 넣지 않습니다. 9단계부터 드문 예고탄, 17단계부터 일부 공격의 좁은 통로처럼 새 도전을 순차적으로 도입합니다. 레이저의 1.05초 이상 예고·비중첩 규칙은 그대로 유지합니다.

레이저는 폭 82~109 게임 좌표의 넓은 띠이며, 매번 예고가 시작된 플레이어 위치를 정확히 통과합니다. 예고 중에는 조준점을 움직이지 않습니다. 가로·세로·두 대각선으로 방향이 섞이고 숫자 카운트다운은 사용하지 않습니다. 1·2·4패턴도 8방향에서 등장합니다. 기본 템포를 2배에서 1.5배로 낮췄으며, 5단계 이후에는 유성우의 회전 순서와 이동 통로·발사 각도의 변주를 통해 새 도전을 줍니다.

### 이동을 요구하는 공격

유성우는 기존 탄 수를 늘리지 않고 한 발을 예고 시점의 플레이어 위치를 통과하는 직선탄으로 배치합니다. 파동은 부채꼴의 실제 탄 하나가 같은 위치를 겨냥하며, 열린 틈을 플레이어 정면에 고정하지 않습니다. 통로는 기존 벽들과 공통 회피 공간을 유지할 수 있을 때 현재 위치에서 벗어난 곳으로 열립니다. 모든 조준은 생성 시점에 고정되고 중간에 추적하지 않으며, 초기 적응 시간·1.5배 템포·단계별 완만한 상승은 유지합니다.

### 8개 패턴 풀

유성우·틈새 비행·경계선·파동에 잔상(발밑 위험 구역), 궤도(회전 위성탄), 압축 구역(열린 방향 탈출), 반사탄(벽 반사)을 추가했습니다. 첫 유성우로 조작을 익힌 뒤에는 8개를 중복 없이 섞어 진행합니다. 다음 8개 묶음에서도 비슷한 계열이 연속되지 않도록 하며, 다음 패턴 이름·회피 요령을 미리 표시합니다. 단계 난도는 패턴 종류와 별도로 완만하게 상승합니다.

정지 상태 통과와 실제 이동 회피를 별도로 검사합니다. 브라우저 전환 테스트는 무적 처리 없이 실제 키보드 이동 경로로 첫 패턴을 통과합니다.

### 실험용 1~8배속

시작·종료 화면의 배속 메뉴에서 현재 밸런스를 기준으로 1×~8×를 선택합니다. 이동·공격·예고·단계 진행 전체가 같은 비율로 빨라집니다. 도전 중과 일시정지 중에는 배속을 바꿀 수 없으며 다음 도전부터 적용됩니다. 점수는 배속을 곱한 가상 시간이 아니라 실제 생존 시간이고, 최고 기록은 배속별로 분리합니다. 기존 기록은 1× 기록으로 유지됩니다. 8×에서도 충돌 계산은 시뮬레이션 시간 기준 최대 1/120초 간격으로 수행합니다.
